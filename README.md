## 2. Обґрунтування захищеної ознаки та аналіз проксі-ознак (п. 5.2)

- **Основна захищена ознака:** `CityTier` (рівень міста: 1 — мегаполіси, 3 — малі міста). Вона безпосередньо відображає географічну та соціально-економічну нерівність (дохід, логістичні можливості). Базовий рівень відтоку між групами суттєво різниться: Tier 1 — 14.5%, Tier 2 — 19.8%, Tier 3 — 21.4%. Використання її в моделі спричинить систематичну дискримінацію в доступі до програм утримання та компенсацій за географічною ознакою.
- **Архітектурне виключення `Gender`:** Ознака статі є захищеною характеристикою відповідно до загальних норм регулювання. Її прогностична сила є вкрай низькою (відтік серед чоловіків 15.5%, серед жінок 17.7%), проте її пряма наявність у `features` створила б неприпустиму пряму гендерну дискримінацію при нарахуванні знижок. Тому список `protected_attributes: [CityTier, Gender]` повністю виключається з конвеєра, але залишається в сирих даних для подальшого вимірювання справедливості на прогнозах.
- **Аналіз проксі-ознак:**
  - **`PreferredPaymentMode`:** Виявлено сильний зв'язок із захищеною ознакою `CityTier` (Cramér's V = 0.44). Зокрема, спосіб оплати `E wallet` зустрічається виключно серед клієнтів із Tier 3. Ознаку залишено у `features` через високу бізнес-значущість для моделювання відтоку, проте зафіксовано ризик непрямого витоку інформації про місто, що потребує обов'язкового моніторингу метрики EOR.
  - **`PreferredLoginDevice`:** Зв'язок із `CityTier` після уніфікації синонімів є незначним (V ≈ 0.01), ознаку залишено у `features` як звичку користування сервісом.

## 3. Обґрунтування схеми ключів model_family (п. 3.4.4)

Обрано рекомендовану дихотомію **`additive / partitioning`**:
- **`additive` (адитивні моделі, наприклад, Logistic Regression):** Обчислюють прогноз як зважену суму ознак ($w^T x$). Чутливі до масштабу та асиметрії розподілів, тому вимагають обов'язкового логарифмування правосторонніх хвостів (`log1p`), стандартизації (`standard_scaler`) та інтерпретованого внеску категорій (One-Hot / WoE).
- **`partitioning` (розбиваючі моделі, наприклад, Random Forest / Decision Trees):** Розбивають простір ознак паралельно осям за допомогою порогових предикатів. Інваріантні до будь-яких монотонних перетворень, що зберігають порядок (шкалювання для них є надлишковою операцією). Для захисту від одиничних екстремальних викидів, що можуть спричинити глибокі перенавчені вузли, використовується вінсоризація (`winsorize`).

Обидві конфігурації (`config_lr.yaml` та `config_rf.yaml`) відрізняються **рівно в один рядок** (`model_family: additive` проти `model_family: partitioning`).

## 5. REFORMS-аудит (Блоки 1–2)

### Модуль 1. Цілі дослідження
- **1a (Популяція):** Клієнти великої платформи електронної комерції (B2C роздрібний продаж побутової техніки, мобільних пристроїв, одягу та бакалії) з історією замовлень та звернень.
- **1b (Обґрунтування):** Популяція визначена структурою вибірки E-Commerce Dataset (Kaggle), що охоплює різні географічні зони (Tier 1–3) та способи взаємодії.
- **1c (Обґрунтування ML):** Зв'язки між задоволеністю, наявністю скарг, перервами в замовленнях та відтоком є нелінійними і містять взаємодії високих порядків. Зафіксовано строгий поріг евристичного бейзлайну: **Recall = 0.85, Precision = 0.34, Accuracy = 0.70**. Впровадження алгоритмічного моделювання є виправданим лише за умови збереження повноти (Recall ≥ 0.80) при суттєвому зростанні точності (Precision ≥ 0.50).

- **2b (Код):** Репозиторій версіонується в Git. Версія коду, що відповідає вимогам Quality Gate 1, зафіксована тегом **`lab1-v1.0`**.
- **2c (Обчислювальне середовище):** Python 3.11 / 3.12, Windows 11. Версії пакетів жорстко закріплені у файлі `requirements.txt` (`pandas`, `numpy`, `scikit-learn`, `openpyxl`, `pyyaml`).
